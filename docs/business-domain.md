# Бизнес-домен: система исполнения ордеров криптовалютной биржи

**Илья · 5130904/40001 · Вариант № 27**

В качестве примера работы системы массового обслуживания рассматривается система исполнения ордеров криптовалютной биржи. Трейдеры двух категорий — VIP и Standard — непрерывно подают заявки на покупку и продажу криптовалюты через торговый терминал или API. Поступающие ордера распределяются между движками исполнения. Если все движки заняты, ордер временно помещается в буфер. При переполнении буфера вновь поступивший ордер получает отказ. После освобождения движка следующий ордер выбирается из буфера с учётом категории трейдера: VIP-ордера всегда обслуживаются раньше Standard.

**Формула:** `ИБ — ИЗ2 — ПЗ1 — Д1ОЗ3 — Д1ОО5 — Д2П1 — Д2Б4 — ОР1 — ОД3`.

| Код | Компонент | Значение |
|---|---|---|
| ИБ | Источник | Бесконечный |
| ИЗ2 | Закон генерации | Равномерный |
| ПЗ1 | Закон обслуживания | Экспоненциальный |
| Д1ОЗ3 | Буферизация | На свободное место |
| Д1ОО5 | Отказ | Вновь пришедшая заявка |
| Д2П1 | Выбор прибора | Приоритет по номеру |
| Д2Б4 | Выбор заявки | Приоритет по номеру источника, по одной |
| ОР1 | Автоматический режим | Сводная таблица |
| ОД3 | Пошаговый режим | Временные диаграммы |

## 1. Элементы бизнес-домена

### 1.1. Источник (ИБ, ИЗ2)

Источниками являются трейдеры биржи двух категорий:

- **VIP-трейдеры** (источник № 1, наивысший приоритет) — крупные институциональные участники рынка: фонды, маркет-мейкеры, банки;
- **Standard-трейдеры** (источник № 2) — розничные участники рынка, совершающие сделки меньшего объёма.

Каждый трейдер подаёт заявки на покупку или продажу криптовалютных активов (BTC, ETH, USDT и др.) через торговый терминал или API биржи.

Источник бесконечный (ИБ): после подачи ордера трейдер продолжает торговлю и через некоторый интервал формирует следующую заявку на протяжении всей торговой сессии. Число потенциальных трейдеров не ограничено.

Интервалы между поступлениями ордеров подчиняются равномерному закону (ИЗ2): в активную торговую сессию трейдеры подают заявки через интервалы из диапазона [a_i, b_i], что соответствует ровной торговой активности.

### 1.2. Буфер (Д1ОЗ3)

Буфером является очередь ордеров ограниченной ёмкости *K* — промежуточное хранилище заявок обеих категорий, ожидающих свободного движка исполнения. Физически это буфер системы матчинга с фиксированным лимитом на число одновременно хранимых ордеров.

По дисциплине Д1ОЗ3 («на свободное место») новый ордер любой категории помещается в **первую свободную ячейку, считая с начала буфера**. Указателя нет, уже стоящие в очереди ордера не сдвигаются. Если ордер был извлечён из середины буфера, освободившуюся ячейку займёт следующий поступивший ордер.

### 1.3. Прибор (ПЗ1)

Приборами являются движки исполнения ордеров — выделенные вычислительные модули биржи. Каждый движок обрабатывает один ордер за раз и выполняет над ним следующие операции:

1. валидация ордера (баланс, лимиты, корректность параметров);
2. поиск встречной заявки в книге ордеров (order book);
3. исполнение сделки и обновление книги ордеров;
4. расчёт комиссии и обновление балансов трейдеров;
5. при необходимости — уведомление о частичном или полном исполнении.

Время обслуживания распределено по экспоненциальному закону (ПЗ1). Большинство ордеров исполняются быстро (шаги 1–4), а редкие крупные ордера требуют частичного исполнения и серии уведомлений (шаг 5) и обслуживаются значительно дольше.

### 1.4. Дисциплина отказа (Д1ОО5)

Если в момент поступления нового ордера все движки заняты и все ячейки буфера заполнены, применяется Д1ОО5 — отказ вновь пришедшей заявке.

Поступивший ордер **любой категории, включая VIP**, немедленно отклоняется без исполнения. Трейдер получает уведомление с кодом `ORDER_REJECTED: queue full`. Содержимое буфера не меняется, стоящие в очереди ордера не затрагиваются. Отклонённый ордер фиксируется в журнале отказов; трейдер может подать заявку повторно.

### 1.5. Дисциплины постановки на обслуживание (Д2П1, Д2Б4)

**Д2Б4** — выбор заявки из буфера по приоритету номера источника, по одной заявке. При освобождении движка из буфера берётся ордер с наименьшим номером источника: ордера VIP-трейдеров (источник № 1) всегда обслуживаются раньше ордеров Standard-трейдеров (источник № 2). Если в буфере несколько ордеров одного источника, выбирается **последний поступивший**.

**Д2П1** — выбор прибора по приоритету номера. При каждом назначении поиск свободного движка начинается с движка № 1 (основного); движок № 2 (резервный) задействуется, только если основной занят.

### 1.6. Заявка

Заявкой является ордер трейдера. Он содержит:

- категорию трейдера (VIP / Standard) и его идентификатор;
- тип ордера (рыночный / лимитный);
- торговую пару (BTC/USDT, ETH/USDT и др.);
- объём и цену;
- метку времени подачи.

Для моделирования у каждой заявки фиксируются:

| Параметр | Смысл |
|---|---|
| t_пост | Момент поступления ордера в систему |
| t_нач | Момент начала исполнения движком |
| t_кон | Момент завершения исполнения |
| T_ож | Время ожидания в буфере = t_нач − t_пост |
| T_обсл | Время исполнения = t_кон − t_нач |
| T_преб | Время пребывания в системе = t_кон − t_пост |

После исполнения результат сделки записывается в историю торгов, балансы трейдеров обновляются, и заявка покидает систему.

### 1.7. Автоматический режим (ОР1)

После завершения моделирования формируется сводная таблица характеристик:

| Характеристика | Описание |
|---|---|
| p_отк | Вероятность отказа по каждой категории трейдеров |
| T_преб | Среднее время пребывания ордера в системе |
| T_БП | Среднее время ожидания в буфере |
| T_обсл | Среднее время исполнения ордера |
| Д_БП | Дисперсия времени ожидания в буфере |
| Д_обсл | Дисперсия времени исполнения |
| K_исп | Коэффициент использования каждого движка |

По таблице анализируется, как число движков, ёмкость буфера и интенсивность торговли влияют на производительность биржи.

### 1.8. Пошаговый режим (ОД3)

В пошаговом режиме отображается временна́я диаграмма работы системы. По горизонтальной оси — модельное время, по вертикальной — источники (VIP и Standard), ячейки буфера и движки исполнения. На диаграмме видны моменты поступления ордеров, периоды ожидания в буфере, периоды занятости каждого движка и моменты отказов. Шагом является интервал модельного времени между соседними особыми событиями (поступление ордера, завершение исполнения).

### 1.9. Диспетчер

Диспетчер в модели — **не человек, а алгоритм**: программный модуль системы матчинга, работающий автоматически. Он состоит из двух частей:

- **диспетчер постановки** — при поступлении ордера выбирает свободный движок (Д2П1), при занятости всех движков ставит ордер в буфер (Д1ОЗ3), а при полном буфере отклоняет его (Д1ОО5);
- **диспетчер выбора** — при освобождении движка выбирает из буфера следующий ордер (Д2Б4).

Решения диспетчера принимаются мгновенно по сравнению со временем исполнения, поэтому время его работы в модели равно нулю.

## 2. Логика работы системы

Трейдер подаёт ордер через торговый терминал. Если есть свободный движок, ордер сразу направляется на исполнение — выбирается движок с наименьшим номером (Д2П1). Если все движки заняты, ордер помещается в первую свободную ячейку буфера, считая с начала (Д1ОЗ3). При освобождении движка из буфера выбирается ордер по Д2Б4: сначала VIP-ордера (источник № 1), затем Standard (источник № 2), а среди ордеров одного источника — последний поступивший. Если в момент поступления все движки и все ячейки буфера заняты, срабатывает Д1ОО5: новый ордер отклоняется, трейдер получает уведомление об отказе, буфер не меняется.
